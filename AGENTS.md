# Листай

Android-читалка с ощущением бумажной книги для телефонов и Fold. Kotlin/Compose,
API 26–36; RU и EN. Пользовательский язык — холодный синий/серый, чистая белая
бумага или графит. Управление напечатано на книге и бумажных вкладках;
постоянных панелей и переключателя fullscreen нет.

## Где работать

- `format/fb2` → `core/model` → `reader/pagination` → `feature/reader`.
  Парсер/модель/пагинация не знают о Compose и не выполняют Android-отрисовку.
- `reader/rendering` — чистая геометрия листа; `feature/reader/bookview` —
  Android measurement, поверхности, кэш, rigid cover и ввод.
- `core/files` — частная копия книги/импорт, `core/database` — Room и DataStore;
  `app/LibraryController` связывает их с жизненным циклом и UI.
- `feature/library` — полка и полёт обложки. Общая обложка — `core/designsystem`.
- `docs/architecture.md` — подробные контракты. `docs/rc1-plan.md` — исходный объём RC;
  `docs/rc2-task.md` — текущая приёмка, `docs/rc1-task.md` — историческая.

## Инварианты и проверка

- Сохранять смысловой `BookLocation`, а не номер страницы. Основное место,
  оглавление, аннотация и визит к примечанию имеют разные anchors.
- Текст/изображения растеризуются до curl; не запускать layout/decode в каждом кадре.
  Поворачиваемая страница содержит контент с первого кадра; обложка жёсткая.
- Импорт копирует исходник; удаление книги не удаляет пользовательский файл.
  Миграции Room сохраняют библиотеку/прогресс/закладки, без destructive fallback.
- Для графики использовать [listai-reader-ui](.agents/skills/listai-reader-ui/SKILL.md),
  для книг/хранилища — [listai-books](.agents/skills/listai-books/SKILL.md).
- Запускать релевантные JVM-тесты; для UI — screenshot validation и затронутые
  сценарии эмулятора. Эталоны обновлять только после осмотра намеренного изменения.
  Не переписывать golden лишь для получения зелёного теста.
- Полный host gate: `./gradlew test lintRelease :app:assembleDebug
  :feature:reader:validateDebugScreenshotTest :feature:library:validateDebugScreenshotTest`.
  JDK 17+; CI использует 21. SDK 36. Физические устройства исключены из текущего плана.
- Версия централизована в `gradle.properties`. Менять её в рамках запроса на выпуск;
  ключи/пароли/локальные пути SDK не включать в Git. Не менять опубликованные теги.

## Выпуск версии

Для сборки подписанного APK, push или выпуска версии в SourceCraft используй
[навык `listai-release`](.agents/skills/listai-release/SKILL.md). Он содержит URL
репозитория, рабочий способ авторизации и пути к существующему постоянному ключу.
Перед запросом URL, входа или нового ключа выполни проверки из этого навыка.

Навыки не расширяют запрос пользователя: задача на ревью не разрешает менять код,
а локальная правка сама по себе не разрешает push или публикацию.
