# Приёмка 1.1

24 сентября 2026 года. `versionName=1.1`, `versionCode=15`, Room schema 4.

## Проверки

- Полный host gate: JVM-тесты, `lintRelease`, debug APK и screenshot validation
  ридера/библиотеки. Все 159 screenshot-сценариев прошли. Осмотрены четыре новых
  эталона настроек (RU/EN, светлая/тёмная тема, крупный текст); изменённый эталон
  пустой полки отражает поддержку EPUB/PDF.
- EPUB: 16 JVM-тестов — EPUB 2/3, spine/TOC, CSS-типографика, изображения, примечания,
  Unicode/UTF-16, ссылки, лимиты ZIP/XML, запрет DTD и external entities.
- PDF: JVM-пагинация сохраняет один исходный лист на страницу и anchors после
  смены метрик и single/spread. Инструментальные тесты проверяют размеры/пустые
  страницы, ограничения, повреждённые и защищённые документы.
- API 36: пять UI-сценариев проверяют долгое нажатие и sharing, меню импорта,
  перестановку с автопрокруткой большой полки, accessibility actions и полный
  mixed EPUB/PDF import → чтение → перелистывание → recreate → sharing.
  Передаваемые bytes и MIME сверяются с исходными файлами.
- API 26: миграции/настройки/порядок полки (8 тестов) и файловое хранилище,
  рекурсивная SAF-папка с циклом, дубликаты, испорченная книга, отмена/rollback,
  сохранение порядка и sharing, PDF-обложка — 16 тестов. На API 36 те же
  8 + 16 сценариев также прошли.
- PDF на API 26: 5 проверок parser/service, 1 обложки и 2 растеризации. На API 36:
  4 parser и 2 растеризации; test отмены legacy-service пропущен как неприменимый.
  Проверены последовательные malformed → valid → encrypted → valid и отсутствие
  оставшегося изолированного процесса.
- Ручной DocumentsUI на API 36: выбрана папка с EPUB, вложенным PDF, битым FB2
  и TXT. Итог: добавлено 2, ошибка 1, пропущен 1; PDF визуально проверен в ридере.
- Подписанный APK установлен на отдельный API 26 эмулятор; холодный запуск успешен
  (`am start -W`, Status ok). В этой подписанной сборке через DocumentsUI также
  импортирована та же реальная папка: добавлено 2, ошибка 1, пропущен 1.
  Подпись совпадает с постоянным ключом прошлых версий.

Локальные артефакты: `out/release/listai-1.1.apk`, соответствующий `.apk.sha256`,
логи и осмотренные скриншоты в `out/qa/v1.1/`.

## Обнаруженные и исправленные регрессии

- Заголовок настроек использует `onSurface` в тёмной теме.
- В SINGLE перелистывание назад возвращает предыдущий лист слева от корешка
  поверх текущего. Четыре JVM-теста проверяют обратную траекторию, вертикальный
  наклон, произвольный anchor, конечные положения и отмену. Добавлены 12 кадров
  ранней/средней/поздней фазы в обеих темах; осмотрены и обновлены четыре прежних
  кадра возврата к форзацу. На API 26 прошли 11 сценариев жестов, отмены, переходов
  по оглавлению/закладкам и возвращения из примечаний, включая проверку записи
  позиции только после завершения перелистывания. Исправленный подписанный APK
  заново установлен на чистые данные API 26; холодный запуск и реальные свайпы
  вперёд → назад прошли, текст исходной страницы восстановлен точно.
  На API 36 также прошёл новый сценарий возврата/отмены в обеих темах.
- Release-up stationary long press потреблялся дочерним clickable; shelf gesture
  теперь обрабатывает это событие раньше и надёжно открывает действия книги.
- Название FB2, заканчивающееся на `.zip`, больше не становится format hint при
  повторном открытии. PDF-marker внутри текста FB2 не определяет формат файла.
- Название sharing-файла ограничено с учётом максимальной UTF-8 длины имени.
- Отчёт отменённого batch учитывает книгу, которая успела атомарно опубликоваться.
- Проверка PDF на Android 8 выполняется в изолированном процессе: ошибка
  предыдущего документа не влияет на следующий импорт.

## Ограничения

Физические устройства не проверялись. Fold-геометрия покрыта существующими
JVM/screenshot-тестами; новый прогон с реальным hinge не выполнялся. EPUB использует
нативную перевёрстку: сложная CSS-раскладка, скрипты, DRM и XML с DTD не поддерживаются.
PDF сохраняет исходную вёрстку, без zoom, поиска и выделения текста; защищённый PDF
нужно предварительно разблокировать. Максимальный исходный файл — 128 МиБ.

При дополнительной проверке перелистывания API 36 эмулятор с GLES translator
завершался с host SIGSEGV. Новый сценарий прошёл с `-gpu swangle` и
`debug.hwui.renderer=skiagl`. Расширенный повтор Stage721/Stage8 на этом backend
не завершился и был остановлен; его не учитываем как успешный. Те же сценарии
прошли на API 26. Это ограничение дополнительного прогона, не падение Android-приложения.

Публикация в SourceCraft не входит в эту локальную подготовку версии.
