# Этап 8 — сноски и физическая полировка

Дата: 2026-09-15. Контракт: [stage8-plan.md](stage8-plan.md).

## Реализация

- `BookDocument.noteIndex` — формат-независимый индекс валидных непустых
  примечаний и каждого вызова в исходных UTF-16 координатах. Повторные ссылки
  имеют собственный `BookLocation`; цитаты, стихи и surrogate pairs не сдвигают
  позицию. Поиск вызовов в диапазоне строки не сканирует весь абзац.
- `FootnotePagination` резервирует нижнюю область **до** создания bitmap.
  На развороте у каждого листа свои сноски. Повторный вызов одного примечания
  на листе не дублирует нижний текст. Книги без разрешённых сносок используют
  прежний алгоритм пагинации без пустой зарезервированной области.
- Нижний текст: serif 82%, hanging indent, короткий холодный разделитель,
  полужирное/курсив/зачёркивание. Длинный фрагмент — до четырёх строк и `… →`.
  Бюджет 30%, до 40% для нескольких коротких примечаний; максимум восемь
  монотонных уточнений. Неразделимые плотные вызовы получают ссылку
  «Ещё N примечаний» / “N more notes”. Измерение большого примечания ограничено
  4096 UTF-16 единицами, исходный полный текст не обрезается.
  Строка переполнения остаётся однострочной даже на узком листе с крупным
  шрифтом: сокращается с `… →`, сохраняя всю область перехода.
- Надстрочные серо-синие метки — без видимых квадратных скобок. Только в
  отображаемой строке скобки заменяются на WORD JOINER той же UTF-16 длины:
  номер не отрывается от слова и следующей пунктуации при переносе.
- `PhysicalNotes` создаёт один непрерывный раздел после основного текста,
  перед задним форзацем/обложкой. Заголовки локализованы, rich-блоки оригинала
  сохранены, отдельного разрыва страницы на каждое примечание нет. Пустые
  примечания исключены; непустые без вызова остаются. Оглавление получает
  условный пункт «Примечания». В разделе собственная нумерация без точек
  прогресса основного текста.
- Вызов в строке и вся нижняя сноска ведут к полному тексту физическим curl.
  Печатная отметка возврата на полях каждого примечания и его продолжения,
  а также Android Back, возвращают к точному месту вызова. При ручном входе
  используется первый реальный вызов; при его отсутствии ложного возврата нет.
- `FootnoteVisit` сохраняется в состоянии чтения при пересоздании и reflow,
  но не подменяет библиотечный прогресс. После выхода из раздела или на полку
  временное посещение сбрасывается. Миграция Room не нужна.
- Повторное открытие обложки при восстановлении Activity больше не считается
  уходом на полку. Адрес сохранённого reader state зависит от стабильного ID
  книги, а не от перезапускаемого счётчика controller session; новая команда
  перехода в живой сессии при этом действительно сбрасывает навигацию.
- Числовой заголовок из FB2 не дублируется в нижней сноске и полном разделе.
  Начальный блок, совпадающий с заголовком note, убирается только из проекции;
  оригинальные данные книги остаются нетронутыми.
- Основной текст и раздел примечаний индексируются параллельно. Уже готовые
  исходные страницы публикуются без ожидания огромного раздела примечаний;
  задняя обложка не появляется до окончательного индекса.
- Сноски и отметки возврата — часть той же подготовленной поверхности,
  что и основной текст. Во время жеста нет layout/raster работы и fade текста.
  Сохраняется общий лимит поверхностей 64 MiB и подготовка только нужных листов.
- Физический рендер: тени зависят от подъёма листа и исчезают после укладки;
  спокойная нейтральная подсветка, отдельная толщина прочитанной/оставшейся
  стопок, раздельные торцы у Fold, мягкая тень жёсткой обложки. Белая бумага
  и цельное растяжение настоящего artwork обложки сохранены.

## Проверка

Проверки выполняются на временных Pixel 7 и Pixel Fold / API 36 / x86_64 /
`swangle`, debug. Fold проверен в раскрытом состоянии на внутреннем дисплее.
Пути артефактов текущего прогона: `/tmp/listai-stage8-qa-7YDOpI`.

- Модель и пагинация: новые тесты индекса/UTF-16, reflow, дедупликации,
  ограничения высоты, переполнения, большого примечания и отсутствия сносок.
- FB2: `fixtures/stage8-notes.fb2` содержит короткие, длинное, повторный вызов,
  непроцитированное примечание, rich-текст, цитату и стихи. Отдельный тест
  связывает результат parser с индексом вызовов, не смешивая notes с reading flow.
- Навигация: условное оглавление, непрерывная проекция, точные повторные origin,
  Saver/reflow, продолжения, коллизии synthetic ID, границы partial index.
- Native raster: реальные StaticLayout, ссылки и области нажатия, богатый
  нижний текст, обрезка, перенос метки, обёртки поверхностей и конечный curl.
- App acceptance: inline/footer → curl → полное примечание → печатный возврат
  в single/spread, Android Back, сохранение места при смене раскладки.
- Real app: импорт FB2 → примечание → Activity recreation → точный возврат;
  ручной вход из оглавления → Back; закрытие на полку → повторное открытие
  исходного текста. Отдельно проверена сериализация reader state через Android
  Bundle/Parcel с новым счётчиком сессии и последующий переход по закладке.
- `ON_STOP` посреди note curl отменяет неподтверждённый переход: исходный
  checkpoint не меняется, после возврата нет отложенного commit, повторный
  переход и Back работают. Старый сценарий закрытия во время page settle
  с пересозданием Activity также проходит.
- Визуальные эталоны: RU/EN, белая/тёмная бумага, разворот, движущиеся листы,
  полный раздел. Старые эталоны физической книги проверяются вместе с новыми.

### Нагрузочный сценарий

`Stage8StressSurfaceTest`: 500 примечаний, первое — около миллиона символов,
500 исходных абзацев. Получено 113 страниц основного текста; измеряемый preview
не превышает 4096 символов; индексы не удерживают платформенные layout.
В итоговом прогоне пагинация заняла 371 ms (single) / 323 ms (spread), отрисовка
13 разнесённых по книге листов — 110 / 109 ms.

Отдельно пагинирован **полный** раздел: 603 страницы, из них 551 занимает
примечание на 1 120 000 символов. Проверено безразрывное покрытие всех символов,
время полного индекса — 591 ms. Отрисованы только четыре разнесённых листа
(индексы 0, 275, 550, 602), включая продолжения с обратной ссылкой: 1046 ms.
Одновременно удерживается один bitmap на 2 304 000 байт; лимит measurement-cache
4 MiB. Наблюдаемый PSS native test process — 97 092–99 836 KiB.

Это один прогон на программном эмуляторе, не FPS-гарантия для телефона,
не доказательство отсутствия утечек и не полное профилирование этапа 9.
Исходный отчёт: `/tmp/listai-stage8-qa-7YDOpI/native/stress-report-final.txt`.
