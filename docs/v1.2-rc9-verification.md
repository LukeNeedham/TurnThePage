# Листай 1.2-rc9 — точный возврат из примечаний

Версия `1.2-rc9`, code `24`, ветка `codex/v1.2`. Локальная проверочная сборка;
push, публикация и теги не выполнялись.

## Причина и исправление

На развороте с последним листом основного текста слева и началом примечаний
справа обычное перелистывание назад очищало `FootnoteVisit`: `commit()`
рассматривал только левый semantic anchor. Печатная кнопка «К тексту» оставалась
видна, но уже использовала первый вызов примечания вместо выбранного читателем.

Теперь существующий контекст примечаний сохраняется, пока открыт хотя бы один
их лист. Основной прогресс не меняется во время такого визита. Явный semantic
anchor внутри примечаний имеет приоритет над первым видимым листом разворота,
чтобы не смещать выбранную правую страницу после изменения размера текста.
Полный выход в основной текст, явный переход в основной текст или на обложку
и закрытие на полку очищают визит. Возврат из оглавления к прежнему примечанию
восстанавливает его исходный адрес вызова.
Естественное первое достижение границы разделов без визита по-прежнему обновляет
прогресс основного текста. Прямой вход через оглавление сохраняет прежний
возврат к первому вызову. Миграция БД не требуется.

Финальный screenshot gate — **PASS**, 2m26s: reader **176/176** выполнены заново,
library **60/60** из актуального результата Gradle `UP-TO-DATE` (библиотека
не менялась). Failures/errors/skipped — 0; эталоны не обновлялись.
Native-съёмка и host screenshot renderer выполнялись последовательно.

Новый `Rc9NoteReturnTest` проверяет реальные жесты и фактически показанный лист:

- Повторное посещение уже закэшированного примечания из более позднего вызова
  в том же исходном абзаце; после возврата сверяются текст, колонцифры и inline hit region.
- Продолжение примечания, смена SPREAD на SINGLE с крупным шрифтом и Android Back.
- Перелистывание вперёд/назад на смешанном развороте и печатная кнопка «К тексту».

Одного сохранённого `ReaderSemanticLocation` недостаточно: тест также находит
именно нажатый вызов среди hit regions реально отображаемой страницы.

API26: **9 уникальных native-сценариев PASS** с учётом целевых повторных прогонов:
три `Rc9NoteReturnTest`, четыре `Stage8AcceptanceTest`, по одному
`ReaderSessionRestorationTest` и `Stage8RestorationTest`. Финальный прогон трёх
новых сценариев зелёный; последний restoration — **1/1**, 11.197s.

API36: **9 уникальных native-сценариев PASS** с учётом целевых повторов.
На широком viewport 2208×1840 прошли три новых Rc9-сценария,
четыре `Stage8AcceptanceTest` и `ReaderSessionRestorationTest`.
На телефоне 1080×2400 отдельно прошли все три Rc9-сценария;
финальный `Stage8RestorationTest` — **1/1**, 39.914s.
Это совокупный результат нескольких прогонов, а не один зелёный запуск всех девяти.

В первых прогонах обнаружились устаревшие предпосылки автоматизации: импорт
теперь открывает обложку и требует нажатия «Читать», а жест следующего листания
должен ждать готовности соседних поверхностей. После адаптации шагов сценарии
перезапущены. Дополнительное «Читать» после открытия с полки было удалено:
этот путь уже восстанавливает открытую книгу. Это были изменения тестов;
production-код и подписанный APK при повторах не менялись.

Отдельный API36-повтор остановился на ожидании закрытия книги после raw touch
по кнопке, хотя тот же APK прошёл этот шаг при диагностическом повторе
(**1/1**, 43.994s). В restoration-тест добавлено ожидание завершения физического
перелистывания; кнопки управления вызываются через semantic click реального UI.
Проверка координат нажатия не является задачей этого restoration-теста;
новые Rc9-сценарии по-прежнему нажимают на реальные hit regions сносок и возврата.

Независимый code review подтвердил границы исправления. Сопоставление native PNG
и semantic-данных подтвердило: до исправления исходный offset `5245` терялся,
после — возвращался именно поздний вызов. Проверены светлая одиночная страница,
разворот и тёмная тема с увеличенным шрифтом после reflow.
Физические устройства не использовались; проверки на эмуляторе не являются
измерением аппаратного FPS.

Финальные crash-буферы приложения пусты. В одном промежуточном API26-логе
сохранена ошибка процесса UiAutomator: попытка отдельного XML dump во время
instrumentation конфликтовала с UiAutomationService. Это сбой тестового
инструмента, не падение приложения; последняя проверка прошла без него.

Журналы и PNG: `out/qa/v1.2-rc9/`; `native-before-fix/` содержит воспроизведение
на неисправленном APK, `native-api36-wide/` — кадры после исправления.
